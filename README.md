## 简历采集（第三大板块，v1.1.0）

侧栏的「简历筛选」现在包含两个可用页面：

- **简历采集**：只在已经打开的 BOSS「沟通」页面中工作，识别到候选人发送的简历请求后点击「同意」，从弹出的简历中提取姓名、电话、邮箱、年龄、性别、城市、学历、经验和求职岗位。两种跑法（2026-08-31 起）：**独立采集**（回复模块关）逐个扫描带红点的未读会话；**一键运行联动**（回复模块开）由自动回复打开会话后顺手在同一趟收简历，先回后收、不再各自扫列表抢未读信号。
- **人才库**：自动接收采集结果，并支持搜索、编辑、删除和 CSV 导出。相同手机号、候选人标识或“姓名 + 岗位”的记录会合并更新，避免重复堆积。

使用步骤：

1. 在 Chrome 扩展管理页加载本项目的 `extension/` 文件夹并点击「重新加载」。不要再加载已经移动或删除的旧 Desktop 路径。
2. 正常登录 BOSS，手动打开「沟通」页面，并保持该标签页处于打开状态。
3. 在插件「大模型回复配置」中配置模型（可选）。电话和邮箱先在本地提取，并会在发送给模型前脱敏；没有模型配置时仍可保存本地能识别出的字段。
4. 打开「简历筛选 → 简历采集」，设置本轮上限、会话间隔和点击前等待，然后点「开始采集」。默认每轮 5 人、会话间隔 60 秒、点击前等待 4 秒。
5. 用「一键运行」做联动时，自动回复与简历采集由编排器协调、可同时进行（先回后收、一会话全办）；仅当手动单独开采集时，才不要再同时手动开自动打招呼/自动回复。遇到安全验证、操作频繁或连续错误时，采集会自动停止，必须人工检查页面后再决定是否继续。

采集逻辑是用户主动启动、串行执行、限制每轮数量和最低间隔的保守流程。它不会绕过验证码、安全验证或平台限制，也不能承诺账号“绝对不会被封”；实际使用仍应遵守平台规则，并先用少量会话人工核对页面识别结果。

## 接口清单（前缀均为 `/api/v1`）

给插件用的 7 个核心接口：

| 方法 | 路径 | 说明 | 认证 |
|---|---|---|---|
| POST | `/auth/send-code` | 发邮箱验证码（开发模式返回 `dev_code`） | 无 |
| POST | `/auth/verify-code` | 校验验证码 → 返回 access/refresh token | 无 |
| POST | `/auth/refresh` | 用 refresh_token 换新 access_token | 无 |
| POST | `/auth/logout` | 登出 | Bearer |
| GET | `/users/me` | 当前用户 + 订阅状态 | Bearer |
| GET | `/products` | 套餐列表 | 无 |
| POST | `/subscriptions` | ~~开通订阅~~（**已移除**：开通/续费一律走下方 admin 接口） | — |

后台管理接口（凭 `X-Admin-Key` 口令，供 `/admin` 页面调用）：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/admin/grant` | 按邮箱一键开通会员（用户不存在自动建号）body `{email, plan_id}` |
| POST | `/admin/extend` | 延长会员 N 天 body `{email, days}` |
| POST | `/admin/cancel` | 取消会员（降为免费版）body `{email}` |
| GET | `/admin/users` | 用户列表及订阅状态、点数余额 |
| POST | `/admin/billing/recharge` | 人工充值点数 body `{email, points, note}`（1 元 = 10 点） |
| GET | `/admin/billing/transactions` | 某用户点数流水（含 token 证据链）`?email=` |
| GET | `/admin`（非 /api/v1） | 后台管理网页 |

**后台口令（ADMIN_KEY）：** 默认 `admin-secret-change-me`，在 `/admin` 页面顶部的「后台口令」框填入即可（浏览器会记住）。
**上线务必改掉**：启动前设环境变量 `export ADMIN_KEY=你的复杂口令`。

原版和你这版的关系：**前端插件几乎原样**（只改了名字、后端地址、加了打分菜单），
**后端是我按插件调用的 7 个接口重写的**（原后端源码拿不到，但接口契约一致，效果相同）。

## 全流程：从零到能用（照着做）

### A. 先在本地跑通（不花钱，验证一切正常）

1. **起后端**（需要你本地有 Python3）：
   ```bash
   cd backend
   pip install -r requirements.txt
   uvicorn main:app --host 0.0.0.0 --port 8080
   ```
   浏览器打开 http://localhost:8080/docs 能看到接口文档就说明起来了。

2. **加载插件**：Chrome → `chrome://extensions` → 打开右上「开发者模式」→
   「加载已解压的扩展程序」→ 选 `extension/` 文件夹。

3. **测登录**：点插件图标 → 侧栏「个人中心」→ 输入任意邮箱 → 点发送验证码。
   因为是**开发模式**，验证码不真发邮件，而是打印在**后端终端**里（也在接口返回的
   `dev_code` 字段）。把它填进去 → 登录成功。

4. **测订阅**：登录后账号是「免费版」。要变 VIP，打开后台页 http://localhost:8080/admin ，
   填入后台口令（`ADMIN_KEY`，开发默认 `admin-secret-change-me`）→「开通会员」填同一邮箱、
   选套餐 → 一键开通。再回插件刷新个人中心 → 变专业版。
   （旧版插件调用的 `POST /api/v1/subscriptions` 已移除，开通一律走 admin 后台。）

5. **测简历打分**：先在「大模型回复配置」里填好你的 LLM（apiUrl/apiKey/model，
   如 DeepSeek）。打开一个直聘候选人简历 → 侧栏「简历打分」→ 点按钮。
   非会员会被拦（提示开通订阅），会员则返回评分。

### B. 部署后端到云服务器（要用了再做，需要你操作）

> 需要你做的：买服务器、设密钥、绑域名。以下命令在服务器上执行。

1. **买一台云服务器**（腾讯云/阿里云轻量应用服务器，2核2G，Ubuntu 22 即可），
   在安全组/防火墙**放行 8080 端口**（或 443，见第 4 步）。

2. **上传 backend/ 并安装**：
   ```bash
   scp -r backend/ ubuntu@你的服务器IP:~/app
   ssh ubuntu@你的服务器IP
   cd ~/app && sudo apt update && sudo apt install -y python3-pip
   pip3 install -r requirements.txt
   ```

3. **设生产环境变量**（关掉开发模式、换随机密钥）：
   ```bash
   export DEV_MODE=false
   export JWT_SECRET=$(openssl rand -hex 32)   # 记下来，重启要用同一个
   ```
   然后用 systemd 或 pm2 守护进程常驻运行：
   ```bash
   pip3 install uvicorn
   nohup uvicorn main:app --host 0.0.0.0 --port 8080 &   # 简易版；正式建议写 systemd
   ```

4. **【强烈建议】配 HTTPS**（原版用 http 明文传 token，是安全隐患，别学）：
   绑一个域名 → 装 Nginx 反代到 127.0.0.1:8080 → 用 certbot 申请 Let's Encrypt 免费证书。
   完成后你的后端地址就是 `https://api.你的域名.com`。

5. **接真实邮件发码**（关掉开发模式后必须做）：
   打开 `backend/core.py` 的 `send_code()`，把那行 `print(...)` 换成调用你的邮件服务
   （阿里云邮件推送 / SendGrid / 企业邮 SMTP）发送 `code`。代码里已标注位置。

6. **把插件指向你的云地址**：编辑 `extension/service-worker/sw.js`，
   把 `http://127.0.0.1:8080` 全部替换成你的地址（如 `https://api.你的域名.com`）。
   `extension/sidepanel/screens/js/profile.js` 顶部注释里的地址也顺手改一下（仅注释，不影响运行）。
   重新加载插件即可。

### C. 支付/收费（沿用原版的半自动模式）

当前订阅方案：

- `plan_weekly`：9.9 元 / 7 天
- `plan_quarterly`：298 元 / 季度（90 天）
- `plan_yearly`：698 元 / 年（365 天）
- `plan_three_year`：1280 元 / 3 年（1095 天）

原版是「扫码付款 → 人工/后台开通订阅」，没接支付网关。你这版一致：
- 个人中心页放的是收款二维码（`extension/sidepanel/screens/images/` 里的两张图，换成你自己的）。
- 用户扫码付款后，你确认收款，在 `/admin` 后台一键开通（`POST /api/v1/admin/grant`）。
- 想全自动，就把开通动作改成"微信/支付宝支付回调成功后再执行"，需要额外接支付平台。

**收费模式（2026-08-27 已拍板，取代早期 BYOK 建议）**：大模型改为**公司托管 + 按量计费**——
模型与密钥部署在公司后端（阿里 dashscope，密钥只放服务器 `.env`），用户不再填自己的 key，
改为按点数付费（1 元 = 10 点，充值走 `/admin` 后台人工确认，与会员收款同动线）。
订阅会员与点数是**双闸门**：会员管"能不能用"，点数管"用多少"。
早期"让客户自己填 key（BYOK）、不承担模型成本"的方案已放弃，打分/回复模块将统一切到托管端点。
